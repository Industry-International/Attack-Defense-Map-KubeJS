================================================================
 KubeJS 全局/局部声明参考（避免重复声明错误）
 更新日期: 2026-06-25
================================================================

在 KubeJS 7 (Rhino) 中：
  - const 在顶层声明 → 全局可见，不可重复声明
  - var   在顶层声明 → 全局可见，可重复声明（但应避免）
  - function           → 全局可见（等同 var）

因此：只要看到某文件用 const 声明了某变量，其他文件就绝对不能再
用 const/var/let 声明同名变量，否则报 redeclaration error。

注意：startup_scripts 和 server_scripts 是两个独立的作用域，
startup 中的 const 不会与 server 中的 const 冲突。
但最佳实践是全局范围内避免重名。

  状态枚举值（持久化友好字符串）：
    VEHICLE_STATE.UNINITIALIZED  = 'uninitialized'  未初始化
    VEHICLE_STATE.IDLE           = 'idle'           空闲
    VEHICLE_STATE.WAITING_CHUNK  = 'waiting_chunk'  等待区块加载
    VEHICLE_STATE.CHUNK_LOADED   = 'chunk_loaded'   区块已加载
    VEHICLE_STATE.DEPLOYED       = 'deployed'       载具已部署
    VEHICLE_STATE.OVER_CAPACITY  = 'over_capacity'  载具超量
    VEHICLE_STATE.UNDER_CAPACITY = 'under_capacity' 载具不足
    VEHICLE_STATE.TIMING         = 'timing'         计时中

  状态转移规则（白名单）：
    UNINITIALIZED        → IDLE
    IDLE                 → WAITING_CHUNK / CHUNK_LOADED
    WAITING_CHUNK        → CHUNK_LOADED / DEPLOYED / IDLE
    CHUNK_LOADED         → DEPLOYED / OVER_CAPACITY / IDLE
    DEPLOYED             → TIMING / OVER_CAPACITY / IDLE
    OVER_CAPACITY        → TIMING / DEPLOYED / CHUNK_LOADED / IDLE
    UNDER_CAPACITY       → IDLE / WAITING_CHUNK / TIMING
    TIMING               → OVER_CAPACITY / CHUNK_LOADED / WAITING_CHUNK / IDLE
    任意状态             → UNINITIALIZED（强制重置）

  注意：WAITING_CHUNK → DEPLOYED 和 TIMING → CHUNK_LOADED 是并列路径，
  避免区块加载后需要多等一 tick 才能部署。

  ======== sbw_vehicle/replenish.js (自动补员系统 - 状态机驱动) ========
    checkReplenish(server)                 — 执行一次全量补员检测
    processVehicleState(server, ...)       — 状态分支处理（switch-case 8状态）
    getCheckTickInterval()                 — 将配置频率(次/秒)转为tick间隔
    startReplenishLoop(server)             — 启动补员定时循环
    stopReplenishLoop()                    — 停止补员定时循环
    initAllVehicleStates(server)           — 强制初始化所有载具状态

    checkInterval 为频率（次/秒），通过 getCheckTickInterval() 转换为实际 tick 间隔：
      checkInterval=1  → 1次/秒 → 每20tick检测一次
      checkInterval=20 → 20次/秒 → 每1tick检测一次
    TIMING 倒计时按 tickStep 递减，确保 respawnDelay(tick) 精确等待。
    补员循环由 /sbw_vehicle start 命令启动。

    局部 let 变量：
      $replenishIntervalId — 定时器ID
      $saveCounter         — 定期保存计数器

 快速核查规则（写新代码前必看）
================================================================

在写新代码前，先检查以下声明是否存在（存在则不可重复声明）：

  1. $ByteTag              ← 已 const，不可重复声明
  2. $IntTag               ← 已 const，不可重复声明
  3. $CompoundTag          ← 已 const，不可重复声明

  4. 以下 const 常量名（server_scripts 作用域）：
     PANE, PROF_TAG_LIST, ATTACH_SLOT_POS, SLOT_TRANSLATE_KEY,
     PROF_CONFIGS, PROFESSIONS, BACKPACK_SLOT_COUNT, BACKPACK_PAGE_SIZE,
     TAOV_RETURNED_BLOCKS_PER_REPAIR_PART, TEAM_REVIVE_CONFIG,
     SBW_VEHICLE_CONFIG, TEAM_ATTACK, TEAM_DEFENSE, TEAM_SPECTATOR,
     TEAM_NONE, JOIN_BATTLE_SCOREHOLDER, JOIN_BATTLE_OBJECTIVE,
     JOIN_BATTLE_TARGET, JOIN_BATTLE_FUNCTION, CLEAR_DELAY_TICKS,
     VEHICLE_STATE, VEHICLE_STATE_TRANSITIONS, VEHICLE_STATE_LIST,
     MODULE_REGISTRY, MODULE_FLAG_PREFIX,
     DEFAULT_STATION_CONFIG, AMMO_ID_MAP, AMMO_KEY_MAP, ← a_config.js
     SAVE_INTERVAL,                                     ← replenish.js 新增
     VEHICLE_CFG, SBW_PREFIX,                           ← main.js
     CFG, PREFIX                                        ← team_revive/main.js

  5. 以下 const 常量名（startup_scripts 作用域，与 server 独立）：
     DYE_COLORS, LOCOMETAL_NORMAL, LOCOMETAL_ANTIBLAST, LOCOMETAL_ANTIPEN,
     CREATE_CASINGS,
     GUI_AMMO_TYPES                                     ← ammo_station_gui.js 新增

  6. 已注册的 item ID（不能再注册同名的）：
     kubejs:profession_selector
     kubejs:team_selector

  7. 已注册的 block ID（不能再注册同名的）：
     kubejs:ammo_crate             — 弹药补给箱（方块驱动版，每20tick扫描补充）

  8. 其他 $ 开头的 Java 类引用（$ListTag, $FloatTag 等，含 $AABB）：
     - 在其他文件中用 var 声明是安全的（不会报错）
     - 但最佳实践是在用到它的文件内用 var 自行声明，不依赖外部
     - $HashMap 在 sbw_vehicle/tools/a_java_refs.js（server）和
       ammo_station_gui.js（startup）各声明一次，不冲突

  9. 所有用 function 声明的全局函数（见第八节）：
     - function 在 Rhino 中是全局可见的（等同 var）
     - 不可在同一作用域内用 const/var 声明同名函数（会冲突）
     - 但可以放心调用，无需重复声明

  10. 用 var 声明的顶层变量（全局可见，可重复声明但应避免）：
      $ammoStationGuiCache — 弹药补给站GUI缓存（startup 作用域）
      $actionBarPlayers    — ActionBar 玩家集合（server 作用域）

  11. global.taovReturnedAutocannon：
      - 通过 global 对象注册，不会和其他 const/var 冲突
      - 访问方式：global.taovReturnedAutocannon.xxx
