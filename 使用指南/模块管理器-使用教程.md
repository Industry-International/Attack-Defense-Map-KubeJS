# 模块管理器（Module Manager）

## 概述

通过 `/module` 命令统一控制各 KubeJS 模块的启用/停用。数据包只需执行对应命令即可激活或关闭模块功能。

```
server_scripts/module_manager/
├── a_registry.js    模块注册表（新增模块在此添加一条记录）
└── main.js          核心逻辑 + /module 命令 + 禁用清理回调机制
```

---

## 命令

| 命令 | 说明 | 权限 | Tab 补全 |
|------|------|------|---------|
| `/module <id> on` | 启用指定模块 | OP 2 | ✅ 模块 ID |
| `/module <id> off` | 停用指定模块 | OP 2 | ✅ 模块 ID |
| `/module list` | 列出所有模块状态 | OP 2 | — |

---

## 已注册模块

| 模块 ID | 名称 | 默认 | 停用时行为 |
|---------|------|------|-----------|
| `spawn_compass` | 出生点选择器 | 关 | 清空在线玩家的选择数据 + server 级可见性 + 内存倒计时 |
| `team_revive` | 队伍复活券 | 关 | —（暂无清理回调） |
| `team` | 队伍选择器 | 关 | —（暂无清理回调） |

> **停用清理机制**：模块可通过 `registerModuleDisableHandler(id, fn)` 注册清理回调，
> 停用时自动执行，无需手动干预。离线的残留数据由模块守卫拦截，不影响功能。

---

## 数据包调用

```mcfunction
# 游戏开始时
/module spawn_compass on
/module team_revive on
/module team on

# 游戏结束时（自动清理 spawn_compass 的选择数据）
/module spawn_compass off
/module team_revive off
/module team off
```

## 新增模块

在 `a_registry.js` 的 `MODULE_REGISTRY` 中添加一条记录：

```js
{ id: 'your_module', name: '显示名称', default: false }
```

然后在对应脚本中用 `isModuleEnabled(server, 'your_module')` 判断启用状态。

如需停用时自动清理数据，在任意脚本中调用：

```js
registerModuleDisableHandler('your_module', function(server) {
  // 清理逻辑，只清在线玩家即可
  var iter = server.players.iterator()
  while (iter.hasNext()) {
    var p = iter.next()
    delete p.persistentData.someKey
  }
})
```

## 全局 API

| 函数 | 说明 | 调用示例 |
|------|------|---------|
| `isModuleEnabled(server, moduleId)` | 判断模块是否启用 | `isModuleEnabled(server, 'spawn_compass')` |
| `setModuleEnabled(server, moduleId, enabled)` | 启用/停用模块 | `setModuleEnabled(server, 'my_mod', true)` |
| `registerModuleDisableHandler(moduleId, handler)` | 注册停用回调（handler 接收 server） | `registerModuleDisableHandler('foo', fn)` |
| `findModule(id)` | 按 ID 查注册记录 | `findModule('team')` |
